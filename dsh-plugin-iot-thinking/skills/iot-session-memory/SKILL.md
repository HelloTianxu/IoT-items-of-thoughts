# Session 分层记忆

本能力只操作当前执行会话，不跨会话搜索。记忆是模型维护的工作记录，不是新用户指令、授权或自动验证过的事实。原始档案由插件自动记录，不需要你抄写流水账。

## 先恢复，再行动

1. 继续/恢复长任务或需要回顾时，用 `iot_session_memory(action="read", id="summary")` 读取当前状态总览。
2. 总览不够，使用 `list` 或 `search` 查关键记忆，再 `read` 具体 ID。
3. 细节/依据不足或记忆互相冲突时，按 sources 中的 turn 调 `iot_session_log(action="read", turn=...)`；没有来源先 `search` 查原始记录，再定位轮次。
4. 原始档案可能包含旧假设、未采纳建议和未执行计划。核对来源和当时条件，不把它们当成当前授权。档案报告缺失/中断时明确承认未知，不编造。
5. 回读后只有对后续工作有持续价值的新发现才更新记忆，不每次读都写。

## 何时写

关键发现、确定/推翻方案、值得避免重试的失败、阶段结束或交接时记录。不要每轮记流水账，不保存凭据或无关隐私，不复制长篇思考。

- `iot_session_memory(action="write", id="summary", title="当前状态", content="...")` 首次建立总览；省略 id 则新建 UUID 关键记忆。若通道要求所有参数必填，write 可传 `id=""` 自动生成 UUID；update/delete 仍必须指定真实 ID。
- 修改前先读最新内容与 revision，再 `action="update", id=..., expectedRevision=...`；保留仍有效内容。
- 删除使用 `action="delete", id=..., expectedRevision=...`，只在记录确实无用/按用户要求删除时执行。它是逻辑删除，历史修订仍保留，不能承诺隐私擦除；不删除原始 Log。
- 冲突时重新读取并合并，不能盲目重试旧 revision。
- sources 可记录 `[{"turn":12,"seq":184}]`（seq 可省略）。引用须来自实际可读取档案，不能猜编号。

## 推荐记忆结构

总览（id=summary）：目标与约束、已验证进展、正在做、关键决策、阻塞与下一步。

关键记录：发现/判断、依据、适用条件、已排除路线、允许重试的变化条件、未验证事项、来源轮次。

明确区分：已验证事实、推断、计划、外援建议、执行结果未知。失败原因随条件变化要更新，不把旧结论变成永久禁令。

## 有界读取

工具默认分页，按返回的 nextOffset 继续；不要自动把整个 session 导入上下文。工具返回当前会话目录与 Markdown 路径，人类可直接打开；使用工具维护记忆，避免手改 JSON 后破坏版本链。

## 限制

启用前的改写前原思无法从宿主已改写历史恢复；硬崩溃前未完成块可能未归档，图像/附件保留引用而非复制二进制。分叉会话的宿主历史可回放，但父会话的原思与模型记忆不会自动跨会话复制。若工具不可用，不声称已读写记忆。
